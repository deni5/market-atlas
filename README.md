# Market·Atlas

Каталог моделей і функцій для прогнозування цін, оцінки ризику та виявлення
аномалій на фінансових ринках. Структура натхненна [Crypto·Atlas](https://volodymyr-sokolov.github.io/atlases/crypto/)
Володимира Соколова.

Чистий статичний сайт — без збірки, без фреймворку. Весь вміст лежить в
одному файлі `data/topics.json`; `index.html` / `assets/app.js` більше
ніколи не потрібно чіпати, щоб додати модель чи посилання.

## Структура проєкту

```
market-atlas/
├── index.html          # каркас сторінки (шапка, hero, фільтри)
├── assets/
│   ├── style.css        # усі стилі
│   └── app.js            # рендер карток, пошук, фільтри, тема
├── data/
│   └── topics.json       # ВЕСЬ контент — 27 тем, 140 моделей
├── vercel.json
└── README.md
```

## Локальний перегляд

`index.html` завантажує `data/topics.json` через `fetch`, тому просто
відкрити файл подвійним кліком (`file://`) не спрацює — браузер заблокує
fetch з локального диска. Потрібен будь-який локальний сервер:

```bash
# варіант 1: Python (є майже завжди)
cd market-atlas
python3 -m http.server 8080
# → http://localhost:8080

# варіант 2: Node
npx serve .
```

## Деплой на Vercel

**Варіант A — через GitHub (рекомендовано, дає автодеплой на кожен push):**
1. Створіть новий репозиторій на GitHub і запуште туди вміст цієї папки.
2. На [vercel.com](https://vercel.com) → **Add New → Project** → оберіть
   репозиторій.
3. Framework Preset: **Other** (це чистий статичний сайт, білд не потрібен).
   Build Command: залиште порожнім. Output Directory: `.` (корінь).
4. Deploy — Vercel видасть посилання типу `market-atlas.vercel.app`.

**Варіант B — напряму з командного рядка (найшвидше для першого запуску):**
```bash
npm install -g vercel      # якщо ще не встановлено
cd market-atlas
vercel                     # деплой у preview
vercel --prod               # деплой у продакшн-домен
```
Оскільки акаунт уже є — досить увійти (`vercel login`) і виконати команди
вище прямо з цієї папки.

## Як додавати посилання на джерела для конкретної моделі

Кожен елемент у `data/topics.json` має поле `links` — спочатку порожнє.
Заповніть тільки ті ключі, для яких є реальне посилання; порожні
автоматично не показуються на картці.

```json
{
  "lvl": "III",
  "name": "Variational Autoencoder",
  "tag": "Autoencoder",
  "desc": "...",
  "links": {
    "paper": "https://arxiv.org/abs/...",
    "hf": "https://huggingface.co/...",
    "kaggle": "https://www.kaggle.com/...",
    "wiki": "https://en.wikipedia.org/wiki/...",
    "more": ""
  }
}
```

Підтримувані ключі: `paper` (наукова стаття), `hf` (Hugging Face),
`kaggle` (датасет/ноутбук), `wiki` (Вікіпедія), `more` (будь-яка інша
доцільна стаття). Значення `""` — просто не показується.

Щоб додати новий ключ типу посилання (наприклад `github`), потрібно
одноразово додати підпис у `REF_LABELS` на початку `assets/app.js`:

```js
const REF_LABELS = {
  paper: "📄 paper",
  hf: "🤗 HF",
  kaggle: "🔗 kaggle",
  wiki: "📚 wiki",
  more: "🌐 link",
  github: "💻 code",   // ← новий тип
};
```

## Як додати нову модель або нову тему

Нова модель — новий об'єкт у масиві `items` відповідної теми:
```json
{ "lvl": "II", "name": "Назва моделі", "tag": "Категорія", "desc": "Опис одним реченням." }
```

Нова тема — новий об'єкт на верхньому рівні масиву TOPICS:
```json
{
  "id": "unique-slug",
  "title": "Назва теми",
  "desc": "Опис теми одним реченням.",
  "num": "28",
  "items": [ ... ]
}
```
`id` використовується як якір навігації (`#unique-slug`) — має бути
унікальним і без пробілів. `num` — просто відображуваний номер розділу
(рядок, можна з провідним нулем: `"28"`).

Після редагування `data/topics.json` жодних інших дій не потрібно —
сторінка перечитує файл при кожному завантаженні.
